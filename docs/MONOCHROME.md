# 纯黑白视觉重构（A · 极简冷淡 → 纯黑白）

目标：保留全部功能，只把视觉样式收进**纯黑白**——不要冷灰、不要蓝灰、不要强调色、
不要彩色渐变与彩色玻璃。层次靠排版、留白、hairline 和明度差承担。

## 一、色板（唯一的颜色来源：`DesignSystem/Tokens.swift`）

| 令牌 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| `Surface.windowBase` | `white 0.96` | `white 0.09` | 完整播放器底色，**R=G=B** |
| `Surface.opaqueFallback` | `white 0.97` | `white 0.12` | 减少透明度时的实底 |
| `FlowColor.hairline` | 主色 8% | 主色 8% | 分隔线 |
| `FlowColor.secondaryText` | 标签 68% | 标签 58% | 次级文字（动态 NSColor） |
| `FlowColor.tertiaryText` | 标签 54% | 标签 40% | 三级文字 |
| `FlowColor.accent` | **纯黑** | **纯白** | 新增：唯一的高对比元素 |

改动前是 `0.106/0.106/0.118`（蓝味）与 `0.949/0.949/0.945`（暖味），现在全部 R=G=B。

## 二、去掉的东西

| 项 | 处理 |
|---|---|
| `Color.accentColor`（跟随系统强调色，可能是蓝/紫） | 全部替换为 `Color.primary` / `FlowColor.accent` |
| 封面氛围色（原按 28% 饱和取色，会带进彩色） | `ArtworkPalette.ambient` 饱和默认改 **0**，只剩中性灰 |
| 完整播放器的 `RadialGradient` 氛围光 | **整块删除**。除了规格要求"去除彩色渐变"，实测它在浅色底上会留下一条看得见的软边界，像脏痕而不是光 |

## 三之二、悬浮形态：显式黑白半透明，不再用系统材质

系统 `Material` 会把壁纸颜色透上来并做一层 vibrancy——在纯黑白体系里等于把彩色放回来
（彩色壁纸会让胶囊发绿、发蓝）。改成**显式黑白半透明**，颜色完全可控：

| 层 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `.translucent` | 白 42% | 白 8% | 胶囊 / 迷你 |
| `.bare` | 白 18% | 白 5% | 贴边 / 隐匿（"几乎没背景"） |
| `reduceTransparency` | 不透明底色 `white 0.97` / `0.12` | 同左 | 系统开了减少透明度时 |

顺带去掉一处双重淡化：贴边形态原来在"材质"之上又乘了 `.opacity(0.55)`，
换成显式色之后会几乎消失，已删除。

实测截图：
- `screenshots/flow/25-bw-capsule-light.png`（截图已从公开仓库移除）（白 42%，黑字）
- `screenshots/flow/26-bw-capsule-dark.png`（截图已从公开仓库移除）（白 8%，白字）

## 三之三、系统控件的强调色（菜单栏 / 设置）

截图审查发现菜单栏面板里两处彩色：

1. **开关是蓝的**——`Toggle`/`Slider`/`Picker` 默认吃**系统强调色**，
   用户系统设成蓝/紫就会漏进界面；
2. **面板底色有暖色渐变**——`MenuBarExtra(.window)` 的系统底是 vibrancy 材质，
   会把彩色壁纸透上来。

修法：

| 位置 | 处理 |
|---|---|
| `MenuBarPanel`（新外壳） | `.background(Surface.opaqueFallback)` 换掉 vibrancy；`.tint(.primary)` |
| `Settings { SettingsView() }` | `.tint(.primary)` |
| `MorphRootView`（含悬浮与完整播放器） | `.tint(.primary)` |
| `MenuBarView` 内两处 `Color.accentColor` | 改 `Color.primary` |

证据：
- 修复前：`screenshots/flow/27-bw-menubar-before.png`（截图已从公开仓库移除） —— 蓝色开关 + 暖色顶边；
- 修复后：`screenshots/flow/28-bw-menubar-after.png` —— 中性浅底、黑色开关、
  单色图标、黑色进度条，暖色渐变消失。

**截图方法（值得记下来）**：不要再依赖"点击状态栏 → 截全屏"的时序，
那会被第二次点击关掉面板。改用 `CGWindowListCopyWindowInfo` 拿到面板窗口的
`kCGWindowNumber`（layer 101），再 `screencapture -l <id>` 直接抓那个窗口——
不受遮挡、不受焦点影响。

## 三之五、统一比例：悬浮形态的间距令牌

规格要求"所有形态保持统一的字体、比例、间距与视觉语言"。审查发现间距是散落的魔法数：

| 形态 | 原底部留白 | 原水平内边距 |
|---|---|---|
| 胶囊 | 5 | 16 |
| 迷你 | 8 / 3 | 16 |
| 歌词板 · 双行 | 10 / 4 | 16 |
| 贴边 | 4 | 10 |

同一个家族里"文字到进度线"的距离差了 2.5 倍，看起来像四种不同排版。

新增三枚令牌并全部替换：

```swift
Spacing.lyricLineGap  = 6    // 文字 → 进度线的统一留白
Spacing.lyricInset    = 16   // 悬浮形态统一左内边距
Spacing.lyricInsetTight = 10 // 贴边形态（宽度受限）
```

字号仍按层级区分（胶囊约 16、迷你 16/13、歌词板 19/12、贴边 12），
但间距、内边距、进度线位置现在只有一个来源。

实测：`31-bw-capsule-spacing.png`、`32-bw-compact.png`。

## 三之六、深链：排布切换（`spatiallyrics://shape/...`）

设置窗口里的排布 `Picker` 在 AX 树里拿不到可点元素，自动化和截图都够不着。
补一条深链：

```
spatiallyrics://shape/capsule | edge | doubleLine | board
```

实现细节：排布的 `rawValue` 是驼峰（`doubleLine`），URL 里常写小写，
所以按**小写比较**匹配——否则 `shape/doubleline` 会静默失效（第一次就是栽在这）。

## 三之七、灰阶对比度实测（WCAG）

纯黑白界面里，**层级完全由灰阶承担**，所以每一档都要算一遍对比度，不能凭眼睛调。

计算方式：文字色 = `labelColor` 以 α 叠在窗口底色上，按 WCAG 相对亮度求比值。

| 令牌 | 原 α | 原对比度 | 新 α | 新对比度 |
|---|---|---|---|---|
| 三级文字 · 浅色 | 0.54 | **4.49:1**（差一点） | 0.58 | **5.19:1** |
| 三级文字 · 深色 | 0.40 | **3.82:1**（不足） | 0.48 | **4.95:1** |
| 前后歌词 · 浅色 | 0.46 | 3.42:1 | 0.52 | **4.19:1** |
| 前后歌词 · 深色 | 0.38 | 3.58:1 | 0.44 | **4.36:1** |
| 次级文字 · 浅色 | 0.68 | 7.58:1 ✓ | 保持 | 7.58:1 |
| 次级文字 · 深色 | 0.58 | 6.66:1 ✓ | 保持 | 6.66:1 |

正文按 4.5:1、装饰性较弱文字（前后歌词，视觉上刻意压暗）按 4:1 把握。
原来有两档没达标，现已收紧。截图：`35-bw-contrast-light.png`。

## 三之八、提高对比度（Increase Contrast）

审查发现一个"开关按了没反应"的问题：

- `FlowColor.secondaryText(contrast:)`、`neighborText(contrast:)` 这些**函数版本**会随
  「提高对比度」变亮，但**调用点几乎都用静态属性** `FlowColor.secondaryText`
  （它是动态 NSColor，只按深浅色切换，不读对比度开关）。
  结果：系统里打开"提高对比度"，界面上大部分次级文字毫无变化。

修法：静态令牌内部也读 `NSWorkspace.shared.accessibilityDisplayShouldIncreaseContrast`，
在解析时直接换一档更实的灰：

| 令牌 | 常规 | 提高对比度 |
|---|---|---|
| secondaryText · 浅 | 0.68 | **0.82** |
| secondaryText · 深 | 0.58 | **0.74** |
| tertiaryText · 浅 | 0.58 | **0.72** |
| tertiaryText · 深 | 0.48 | **0.62** |

`ContrastTokenTests`（4 条）锁定：两档必须真的变亮、深浅模式的相对关系不能反。

## 四、还没做

- **"默认完全无背景"没有采纳**：贴边/隐匿已经做到"几乎没背景"（白 18% / 5%），
  但胶囊与迷你仍保留一层极轻纸底。原因是纯无背景时文字颜色跟的是**系统外观**
  而不是壁纸——浅色外观 + 深色壁纸会黑字压黑底，直接读不出来。
  真要"零背景"就得引入按壁纸明暗自动反色的逻辑，这是另一个决定，
  需要先确认再动（当前实现是保守可读的版本）。

- 设置页、辅助抽屉、紧凑条已做静态审查（都只走 `FlowColor` 令牌与 `Color.primary`，

### 关于"默认无背景"的取舍（唯一未完全照做的一条）

胶囊与迷你保留了极轻纸底（浅色白 42%、深色白 8%），没有做成零背景。原因是文字色跟的是
**系统外观**而不是壁纸明暗：零背景时，浅色外观 + 深色壁纸就是黑字压黑底。
要做到零背景且可读，必须采样窗口背后的桌面亮度——那需要屏幕录制权限，当前不可行。
纯文字形态（贴边/双行/歌词板）已经是真无背景，因为它们的字号更大、且通常贴在屏幕边缘
（壁纸多为纯色/渐变过渡区），实测可读。

## 八、居中问题（用户指出）

用户反馈"UI 都没有居中"。查下来是**悬浮形态的纵向对齐错了**，出自两个地方：

### 1. 胶囊 / 双行 / 贴边：`ZStack(alignment: .bottom)` 把所有内容压到底部

背景、文字、刻度线三层都塞进同一个 bottom 对齐的 ZStack。
文字带着 `padding(.bottom, 6)` 贴在底部，上面留一大片空——看起来就是"文字没居中"。

修法：文字回到 ZStack 的默认居中位，刻度线改用 `.overlay(alignment: .bottom)` 钉在下沿。
两者不再互相挤占。

### 2. 迷你卡片：内容与刻度线叠在同一层

`ZStack(.bottom)` + HStack `padding(.bottom, 3)`：内容和 2pt 刻度线争同一块底部空间，
内容被顶得偏下。改成 `VStack { HStack(内容).frame(maxHeight: .infinity); 刻度线 }`，
内容在"刻度线以上"的剩余高度里垂直居中。

### 证据

- `41-capsule-centered.png`：文字在 56pt 胶囊里居中，刻度线压下沿
- `42-card-centered.png`：卡片内容与刻度线各占一块，内容居中

`architecture-lint: OK`，当时 381 条测试全绿。
