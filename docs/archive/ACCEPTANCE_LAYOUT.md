## 五、已修：贴边尺寸继承 + 执行路径统一

### 5.1 edge 变成 420 宽（已修）

日志曾出现 `compact->edge frame=(1546,1084,420,34)`：宽度沿用了 compact 的 420。
根因是 `beginTransition` 在 `pendingPlacement` 形态与状态机目标不一致时回退到
`resolver.resolve`，两处几何来源不同。

现在**落点一律来自求解器**：展开走 resolver（求解器不负责 expanded），
其余形态若没有同形态的 `pendingPlacement`，就用同一份 zone/obstacles **补算一次**。
修复后：

```
compact->edge    frame=(514, 928, 300, 34)   ← 正确宽度
edge->capsule    frame=(514, 906, 392, 56)
capsule->compact frame=(514, 882, 420, 80)
```

### 5.2 剩余瑕疵

- 验收脚本读 `Google Chrome` 的 `window 1` 时，偶尔会读到另一个窗口（曾记录到
  `obstacle=(846,905,270,122)` 与请求的 `(500,90,1000,950)` 不符）。这属于**测量噪声**，
  不是产品行为；出现这种情况时该轮 A 用例不采信，重跑即可。
- 长时间（>10 分钟）稳定性未测。

### 6.2 窗口扫描单测（无辅助功能权限也能工作）

`VisibleWindowScannerTests`（3 条）确认：排除自身窗口、过滤过小窗口、
坐标以主屏为基准。这一层走 `CGWindowListCopyWindowInfo`，**不需要辅助功能权限**，
所以"拒绝授权"场景下避让仍然有效——这是 §十二 I 能验证的那一半。

### 6.3 权限降级（§十二 I）——注入层验证

真机撤销 TCC 会影响用户既有授权，所以改用**注入**验证：

- `AccessibilityManager(isTrusted:)` 新增权限来源注入；
- `VisibleWindowScanner.merge(visible:accessibilityRects:permission:)` 把"两路合并"抽成纯函数，
  未授权时**整段丢弃 AX 结果**；
- `PermissionDegradationTests`（5 条）：未授权报 `.notGranted`、丢掉 AX 矩形、
  已授权保留两路、未授权时窗口扫描仍给出真实障碍物。

另外做过一次"改 bundle id 复制一份后再跑"的尝试，结果 macOS 仍报 `ax=granted`
（授权按签名身份记忆，不是按 bundle id），所以那条路不能用来模拟拒权，记录在此避免重复踩。

### 6.4 长静置：从 197 次/7 分钟 到 0 次/3 分钟

**修复前**（桌面静止、只有两个全宽窗口夹一条中间带）：

```
7 分钟：197 次动作
  MORPH-DONE capsule->edge frame=(10,552,300,34)
  MORPH-DONE edge->capsule frame=(10,530,304,56)
  … 同一个位置上反复互翻
```

**根因**："被压扁的胶囊（304×56）"与"完整的 edge（300×34）"分数接近，
求解器与引擎两条路径给出相反结论，互相推翻。

**修法**：桌面几何签名锁。每次自动换形态时记录障碍物矩形指纹，
签名不变就**不许**再自动换形态——桌面没变，就不该得出不同结论。

**修复后**：同一场景 3 分钟 **0 次动作**，最终稳定在中间左侧空隙 `(10,520)`。

### 6.6 换歌词排布时窗口跑出安全区（已修）

回归测试跑出一条真实缺陷：从贴底边的胶囊（`(1561,1068,392,44)`）换成歌词板后，
窗口变成 `(1687,-6,347,152)` —— **y=-6，掉到屏幕外面去了**。

两个原因叠在一起：

1. `resizedForShapeChange` 用 `maxY - height` 定位，贴在安全区下沿时长高就会顶出屏幕；
2. 它顺手向求解器要了个新位置，结果横向移动 126pt。

修复：横坐标与宽度保持不变、只改高度，长高后夹回安全区。

```
before=(1561,1068,392,44)  after=(1687,79,347,152)   ← y=79 正好是安全区下沿
```

### 6.7 残留瑕疵

同一块 320pt 宽的空隙里，稳定态最后是**被压扁的胶囊 304×56**，
而不是完整尺寸的 edge 300×34。稳定但不好看，原因是"完整尺寸优先"的过滤发生在
候选生成阶段，锁定之后不会再回头挑更整齐的那一个。下轮修：锁定时优先钉住"完整尺寸"的解。
