# FLOW 全功能体验审计 · 2026-11-15

> **历史文档，不再随代码更新。** 2026-11-15 的体验审计，问题多数已修（文中逐条标注）；当时音源只有 B 站。

**测试对象**：Release 构建 `SpatialLyricsPlayer.app`（`/tmp/slp-release`）
**测试方式**：真实鼠标 / 键盘 / 全局热键 / 系统级截图 + AX（辅助功能）树逐元素取证，不读代码下结论；每条结论都有可复现的操作序列与像素或属性证据。
**对标基准**：QQ 音乐（macOS）、网易云音乐（macOS）的完成度。
**覆盖**：完整形态全部控件、迷你/胶囊/贴边形态、队列抽屉、资料库抽屉、快捷设置抽屉、歌单弹层、设置窗口全部 10 个分区、进度与音量、播放模式、歌词跳转、搜索、推荐列表、收藏、形态热键、空格键、退出重启恢复。

---

## 0. 总评

核心体验（桌面歌词 + 卡片形变 + 点击进度）是成立的，工程底子比一般独立播放器扎实。但**作为"能听歌的东西"，它在数据正确性和状态一致性上有三处会直接让用户失去播放能力**，并且有大量"看起来能用、点了没反应"的控件。

以 QQ 音乐 / 网易云的完成度衡量：

| 维度 | 现状 | 差距 |
|---|---|---|
| 曲目信息正确性 | 三处界面三种标题 | **最大短板**，用户会觉得"这是 B 站壳子" |
| 播放控制可靠性 | 静音丢音量、曲末卡死、上一首清空 | 不可接受 |
| 歌词体验 | 同步滚动 + 点击跳转，但无逐字/翻译/字号 | 缺 QQ 音乐的基础档 |
| 内容供给 | 一个 B 站搜索 + 榜单，常被风控 | 没有排行榜/每日推荐/歌单生态 |
| 设置完整度 | 分区齐全、说明详尽 | 若干项是只读文本，实际不可改 |
| 视觉一致性 | 主界面克制有品 | 设置页与主界面是两套组件语言 |

## 1. P0 — 会让用户失去播放能力

### P0-1 静音一次，音量永久归零并写进磁盘

**复现**：音量拖到 56% → 点静音 → 再点取消静音。

| 状态 | 音量读数 | 图标 | `settings.engineVolume` |
|---|---|---|---|
| 静音前 | 56% | 静音 | 0.5625 |
| 静音后 | 56% | 取消静音 | 0.5625 |
| **取消静音后** | **0%** | **仍是"取消静音"** | **0** |

**证据**：`AXValueDescription` 从 `56%` → `0%`；图标仍为 `speaker.slash`；`defaults read com.yg.spatiallyrics settings.engineVolume` = `0`。

**后果**：取消静音后没有声音，用户只会以为"这软件坏了"；而且 `0` 被持久化，设置里「默认音量」从此显示 0%。实测重启后设置页确实显示「默认音量 0%」，但主界面滑块显示 100%——两处又互相不一致。

**根因方向**：`TransportBand.volumeControl` 里 `HairlineSlider` 的 `onChange(of: volumeValue)` 会把**程序写入**的 0 当成用户操作再回灌 `setVolume(0)` + `setEngineVolume(0)`；`syncFromModel()` 又用 `isMuted ? 0 : volume` 写进同一个绑定，形成回环。`PlaybackEngine.setVolume` 里 `isMuted = volume == 0` 把这条回环固化成"永远静音"。

---

### P0-2 队列第一首按「上一首」→ 停止播放 + 清空当前曲目

**复现**：队列里 23 首、当前正在第一首（`情歌`），按播放条上的「上一首」。

**结果**：曲目被卸载，界面退回浏览首页「还没有播放」，`0:00 / 0:00`，Now Playing 信息被清除。

**证据**：系统日志 `Clearing nowPlayingInfo`；截图 `05-after-prev.png`。

**根因方向**：`PlaybackQueue.regress()` 在 `index == 0` 且 `repeatMode != .all` 时返回 `nil`；`PlaybackEngine.perform` 对 `neighbor == nil` 直接 `dispatch(.stop)`。

**对标**：QQ 音乐 / 网易云 / Apple Music 的「上一首」都有 3 秒规则——播过 3 秒就重头播本曲，否则跳上一首；**永远不该把当前曲目清掉**。

---

### P0-3 曲目播完不续播，界面停在"播放中"但进度冻死

**复现**：重启恢复到 `3:49 / 3:49`（曲末），按播放。

**结果**：播放键变成暂停图标（状态=播放中），进度永久停在 `3:49`，连读 5 秒不动，也没有声音。

**证据**：两次间隔 2.5 秒读同一 AX 文本均为 `3:49`；进度 `AXValueDescription` = `100%`。

**后果**：这是一个"看起来在放、其实死了"的状态，用户唯一的出路是手动点下一首。

## 2. P1 — 一眼就能看出"这不是个音乐 App"

### P1-1 歌名/歌手解析只在完整播放器里生效

同一首歌 `愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲`（UP：JLRS-jayfm）在四处显示：

| 界面 | 第一行 | 第二行 |
|---|---|---|
| 完整播放器（detail 成功） | 鸣潮卡提希娅主题曲 | 愿戴荣光坠入天渊 |
| 完整播放器（detail 失败） | 愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲 | JLRS-jayfm |
| 队列抽屉 | 愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲 | JLRS-jayfm |
| 迷你条 | 愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲 | JLRS-jayfm |

另一首 `英雄主义【完整版】`：完整播放器显示 `英雄主义 / 在虚无中永存`，队列显示 `英雄主义【完整版】 / 在虚无中永存`。

**根因方向**：`ExpandedPlayerView` 依赖第二次网络请求 `service.detail(for:)` 拿 `songTitle`/`artist`，失败就回落 `model.displayTitle`（原始 `track.title`）；`AuxiliaryDrawer` / `CompactBarView` / `floatingLine` 完全不解析。仓库里已有 `BiliLyrics.parseTitle`，只是没有在所有出口使用。

### P1-2 解析会把歌名和歌手颠倒

`愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲` → 歌名 `鸣潮卡提希娅主题曲`，歌手 `愿戴荣光坠入天渊`。

正确应该是歌名 `愿戴荣光坠入天渊`，`《鸣潮》卡提希娅主题曲` 是副标题。按 `｜` 切分并假定"右边是歌名"在这条数据上正好反过来。用户看到的是一首根本不存在的歌。

### P1-3 无歌词时，把原始视频标题当歌词放大显示

迷你/胶囊态在没有歌词时，`floatingLine` 回落到 `track.title`：

- 40pt 大字显示 `愿戴荣光坠入天渊｜《鸣潮》卡提希娅主题曲`
- 而它正上方 18pt 已经显示同一段文字

**同一块区域把同一句话写了两遍，一遍还特别大**（截图 `k6.png`）。展开播放器的歌词区则用 `compactTitle` 截断到 18 字——两套规则。

### P1-4 「点右键换一版」指向一个不存在的交互

展开播放器无歌词时提示：**「在歌词区点右键可以换一版」**。

但 `.contextMenu` 只挂在 `LyricFieldView`（悬浮形态用）；展开播放器用的是 `LyricScrollView`，**没有 context menu**。实测右键无任何反应。这是该状态下唯一给出的补救路径，却是死的。

### P1-5 顶栏星形按钮 label 叫「收藏」，实际打开资料库

同一屏上有两个图标相同、无障碍标签相同（`收藏` / `star`）的按钮：

- 顶栏 `[819,467]`：`toggle(.library)` —— 打开资料库抽屉
- 详情面板 `[38,863]`：`toggleFavorite` —— 真的收藏

实测点顶栏那个，弹出来的是「资料库 · 收藏 · 5 首」。收藏后详情面板的星变成 `star.fill`，顶栏那个仍然是空心 `star`——**同一概念在同一屏上有两种视觉状态**。

### P1-6 迷你条没有「上一首」

迷你形态只有 `播放 / 暂停` 和 `下一首`。QQ 音乐的迷你条是 `上一首 / 播放 / 下一首`。

### P1-7 鼠标穿透打开后，形态热键静默失效且无任何提示

**复现**：⌃⌥K 连按到某个形态后（此时 `isClickThrough` 被持久化为 `true`），再按 ⌃⌥K 6 次 → 窗口尺寸与截图 sha256 **完全不变**（`3b885b96` ×6）。按 ⌃⌥L 关掉穿透后，⌃⌥K 立刻恢复。

**后果**：面板既不响应鼠标（看不见任何提示），也不再响应形态热键，用户会认为程序卡死。

### P1-8 形态循环漏掉「隐藏」，但说明文案承诺了它

设置 → 快捷键 写：**「按宽松顺序循环：完整 → 迷你 → 胶囊 → 贴边 → 隐藏」**

`MorphWindowController.cycleMorphology()` 实际是 `[.expanded, .compact, .capsule, .edge]`，**没有 `.dormant`**。

同时：切到胶囊与贴边后，窗口尺寸出现 `393×62 / 393×58 / 394×66` 多种值——同一形态尺寸不稳定。

### P1-9 空闲态播放键 enabled 却点不动，且队列仍标「正在播放」

「回到浏览首页」后：transport 显示 `0:00 / 0:00`、`还没有播放`，但队列抽屉第一行仍带波形图标标着"正在播放"，左栏还有「接下来 / 01 英雄主义 / 还有 22 首」。

此时 `播放` 按钮 `AXEnabled = true`（`上一首/下一首` 是 `false`），点下去没有任何反应。

**要么启用它开始播队列，要么置灰。**

### P1-10 B 站账号没有登录入口（已修 · 见 §30）

设置 → 在线音乐：`B 站账号  未登录 B 站`，下面写着「登录后才能读收藏夹、播放历史，并解锁高音质（大会员可到 HiFi 无损 / Hi-Res）」。

整页翻到底（切歌淡入淡出 / 电台连播 / 离线缓存），**没有任何"登录"按钮或入口**。承诺的能力一个都够不着。

### P1-11 资料库底部计数是错的

界面底部写着 `5 首`，但同一抽屉里只列出 2 行；查数据库 `ZFAVORITERECORD` 也**只有 2 条**记录。

收藏一首之后列表立刻多出一行（`英雄主义【完整版】` 插到最前），计数依然停在 `5 首`。这个数字既不等于实际条数，也不随收藏变化，是一处独立于列表的错误来源。

### P1-12 「清空待播」点了没反应

队列抽屉底部有 `🗑 清空待播`，实测点击后计数仍为 `2 / 2`，列表一条没少。

实现是 `clearLater()`，只清 `later` 缓冲区；主队列条目不在其中。按钮名承诺"清空待播"，行为却什么都不做，也没有确认与撤销。

### P1-13 睡眠定时只能开、不能关

设置 → 播放 → 倒计时：只有 `30 分 / 60 分 / 90 分` 三个裸数字。

- 点 `30 分`：出现选中底纹，表示已生效。
- **再点一次 `30 分`：截图 sha256 完全不变**，无法取消。
- 没有「关闭」项，没有 15 分，没有自定义时长。
- **没有剩余时间显示**（QQ 音乐会显示 `29:58` 并给一个"取消定时"）。

一旦开了定时，用户只能等它到点或者退出应用。

### P1-14 退出前 23 首，重启后只剩 2 首

退出前：左栏显示「接下来 / 01 英雄主义 / 还有 22 首」，队列抽屉显示 `1 / 23`。
重启后：同一队列只剩 `2 / 2`。

曲目、进度、播放模式都恢复了，但**队列大部分条目没有恢复**。

## 3. P2 — 打磨不足

### 信息架构

- **设置页是文档，不是界面**。每行都有 2–4 行说明，例如「默认开启——FLOW 的音源就是 B 站，关掉之后只能看到界面。关闭后应用完全不发起网络请求，已缓存的封面与歌词仍然可用。」四行解释一个开关。QQ 音乐只用一行标签 + 一个 `?`。
- **大量行看起来只读，其实是设置项**：`关闭完整播放器时 → 收进菜单栏`、`界面语言 → 跟随系统`、`当前曲目偏移 → 0 ms`、`循环与随机 → 单曲循环`、`B 站账号 → 未登录 B 站`、`会员状态 → 游客：标准音质`。没有下拉箭头、没有按钮外观，用户不知道该不该点。
- **浮点数用调试格式**：`15.00`、`8.00`、`1.00×`、`95%`。QQ 音乐写「大 / 中 / 小」。
- **滑块体系两套**：主界面是自定义 hairline 滑块（2pt 轨道、无滑块，hover 才出现），设置页是系统 `Slider`（白圆点、粗轨道）。同一个 App 里两种物理语言。
- **设置值离控件很远**：滑块在 x≈1095 结束，数值在 x≈1190，中间 95pt 空白。

### 无障碍

- 快捷设置抽屉里 5 个 `AXCheckBox` **全部没有名称**（标签是同级 `AXStaticText`，没有关联），滑块同样无名。
- 播放进度与音量滑块 `AXSubrole = nil`，VoiceOver 不认作滑块；`AXValue` 读不到，只有 `AXValueDescription`（`57%`）。
- 队列每一行渲染两段完全相同的无障碍文本（`正在播放：英雄主义【完整版】` ×2），读屏会把标题念两遍。
- 搜索输入框 `AXTextField` 无 description/label；placeholder「搜索 B 站音乐」对 AX 不可见。

### 视觉与细节

- **迷你条进度线高 1pt，距窗口底边 3pt**，鼠标几乎无法按准，也没有拖动时的目标时间气泡。
- **迷你形态高度随标题长度在 186 / 217 / 240 之间跳动**，卡片忽高忽低。
- **空态两段重复文案**：迷你形态 `还没有播放 / 在完整播放器里搜索 B 站音乐` 与 `未在播放 / 点击打开完整播放器，搜索你想听的音乐`。两句话说的是同一件事。
- **空态说"点击打开完整播放器"却没说点哪里**。
- **歌单弹层是 470×368 的无标题浮层**：顶部 200pt 全空，关闭按钮 `✕ 关闭` 放在右下角，不像 macOS sheet。
- **推荐列表是 B 站搜索结果直出**：无封面缩略图、无序号、无 hover 播放/收藏/更多、无"更多"入口。标题就是视频标题。
- **描述区贴 B 站视频简介**：`音响：真力1234 · 录音MIC：纽曼149 2支 · 录音设备：SSL Duality Delta Pro Station`——对音乐场景是噪音。
- **封面缺失**：`英雄主义`、`愿戴荣光坠入天渊` 两条都显示音符占位图，而已播放的 `情歌` 有封面。
- **顶栏常驻「未登录 B 站 · 自动」**：把账号状态和音质策略放在主标题旁边，读取成本高且没动作。
- **关于页只有三段散文**：没有检查更新、反馈、开源许可、致谢。版本 `0.1.0 (1)`。
- **每 2 秒一次 `TCCAccessRequest()`**：日志刷屏，权限状态被高频轮询。

## 4. P3

- `播放模式` 与 `随机播放` 是两个独立开关，而 QQ 音乐/网易云是"顺序 / 单曲 / 列表 / 随机"四态轮转。
- **`顺序` 与 `列表循环` 图标完全相同**（都是 `repeat`），只靠颜色区分；用户无法判断循环状态。
- 恢复播放时会停在曲末（`3:49 / 3:49`），而不是回到 0:00 或上一次的有效位置。
- `Esc` 会把窗口收起成迷你形态——没有任何地方提到这个键。
- 设置页滚轮在窗口下边界之外无效（需把光标移进窗口）。
- `离线缓存 41.5 MB` 旁的「清理」无二次确认。
- 资料库只有「收藏」一个分区；B 站收藏夹 / 播放历史因为未登录永远是空的。

## 6. 已验证可用的部分（不是问题，是资产）

- **进度点击/拖动精确**：点 20% → `0:53`，点 85% → `3:44`，拖到 77% → `3:21`，误差 < 1 秒。
- **歌词行点击跳转**：前跳 `1:33 → 1:45`、后跳 `2:02 → 1:50`，跳完继续播。
- **空格**：暂停 ↔ 播放，正常。
- **⌃⌥H**：显示/隐藏生效（在设置窗口处于前台时也能响应）。
- **⌃⌥L**：穿透开关生效。
- **收藏**：详情面板星形切换 `star` ↔ `star.fill`，写入资料库。
- **形态收缩/展开**：点卡片主体与点 `chevron.down` 都能工作。
- **重启恢复**：曲目、队列、进度、播放模式都恢复了，且不自动播放（符合预期）。

- **架构分层的 lint** 仍然通过。

## 7. 未能验证（诚实说明）

- **右键菜单**：`mcp` 宿主吞掉了 CGEvent 右键事件，队列行与歌词区的 `.contextMenu` 无法触发，因此"换一版歌词""从队列移除"两条路径未实测。
- **键盘输入**：系统输入法（SCIM 拼音）截获了所有合成的 ASCII 键入；`AXUIElementSetAttributeValue` 直接写文本框又不会驱动 SwiftUI 绑定（读到的 `AXValue` 有字，但 `query` 仍为空）。因此**搜索这条链路整体未验证**——包括"输入后是否出现搜索按钮""回车是否触发搜索""结果页长什么样"。代码里 `OnlineHomeView.searchField` 有 `query.isEmpty ? 提示 : 搜索按钮` 的分支，不能据此断言按钮不存在。
- **菜单栏弹层**：`MenuBarExtra` 在代码里存在，但无法在无人值守环境点击验证。
- **全屏时自动隐藏、多显示器、耳机拔出暂停、开机自启、桌面小组件**：需要人工插拔/切屏，未覆盖。
- **辅助功能授权**：本机未授权，所以「自动避让」是降级运行，避让本身未验证。
- **B 站风控**：测试期间多次返回 `-352`，推荐榜单时好时坏，这本身是体验问题（见 §5 内容供给行）。

## 8. 建议修复顺序

1. **P0-1 静音归零**：`HairlineSlider` 区分"用户操作"与"程序同步"，不要用双向 `onChange` 回灌；`setVolume` 不要用 `volume == 0` 推导 `isMuted`。
2. **P0-2 上一首清空**：`neighbor == nil` 时不要 `stop`；`regress()` 先判断 3 秒规则，再到边界时重头播本曲。
3. **P0-3 曲末卡死**：EOF 交给状态机，按 `repeatMode` 决定单曲重播 / 下一首 / 停止。
4. **P1-1 + P1-2 标题解析**：把 `parseTitle` 提到 `Track` 构造层，队列/资料库/迷你条/悬浮行统一用一份；修正 `｜` 切分方向（左侧是歌名）。
5. **P1-4 右键提示**：给 `LyricScrollView` 补上同一个 `.contextMenu`，或改掉文案。
6. **P1-5 双星**：顶栏那颗换成 `music.note.list` / 「资料库」。
7. **P1-7 穿透与热键**：穿透开启时在卡片上加一个极小的状态标记（或让形态热键仍然生效）。
8. **P1-10 登录入口**：在线音乐页补「登录 B 站」按钮与二维码流程。
9. **P1-13 定时关闭**：补"关闭"项与剩余时间；`倒计时` 改成与 `到点淡出` 同一种下拉或分段控件。
10. **P1-12 清空待播**：要么真的清空可见队列（加确认 + 撤销），要么改名为"清空稍后播放"。
11. **P1-11 资料库计数**：读数来自列表本身，而不是另一套统计。
12. **P1-14 队列恢复**：把 `items` 一起持久化，而不是只存当前曲目。
